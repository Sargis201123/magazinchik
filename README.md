# Магазинчик

Пиксельный симулятор магазина для Telegram Mini App. Дизайн и план описаны в [docs/GDD.md](docs/GDD.md).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173 (?lang=en — английский)
npm test         # тесты игровой логики
npm run build    # сборка в dist/
npm run sim      # симулятор экономики (баланс)
npm run e2e      # автопроверка: целый игровой день в браузере и снимки (см. ниже)
python3 art/sprites.py  # перерисовать спрайты в public/assets
```

## Структура

- `src/game` — игровая логика без Phaser (экономика, сохранения), покрыта тестами.
- `src/scenes` — сцены Phaser: `BootScene` (загрузка спрайтов), `StoreScene` (магазин), `layout.ts` (планировки помещений).
- `art/sprites.py` — вся пиксельная графика: пиксельные карты и палитра, результат в `public/assets`. Там же иконка `public/favicon.png` и `public/icon-512.png` (аватарка бота: BotFather → /setuserpic).
- Атлас: картинки мира, которые грузит Phaser (список — `src/scenes/textures.ts`), сборка сама складывает
  в один лист `assets/atlas0.png` + `atlas0.json` (`scripts/atlas.ts`, плагин в `vite.config.ts`; в
  `npm run dev` лист собирается на лету и пересобирается, когда `art/*.py` перерисовали картинки).
  Видеокарта рисует соседние спрайты одной пачкой, а игра грузит несколько файлов вместо восьми сотен.
  Новый спрайт — имя в `textures.ts`, больше ничего: в коде сцены он доступен по своему имени, как раньше.
  `textures.ts` — голые данные без импортов (его читает `vite.config.ts`, и правка экономики не перезапускает
  сервер разработки); товары (`item_*`, `crate_*`) и гардероб (`w_*`) сборка находит по именам файлов,
  игра — по своим спискам (`worldTextures.ts`), совпадение проверяет `tests/textures.test.ts`.
  Меню (DOM) берут картинки мира и значки `ico_*` из тех же листов (`src/ui/sheet.ts`: `sheetPng(key)`
  вместо `png(key)`) — без отдельных запросов; чего в листах нет (портреты, газеты), грузится файлом.
- `src/platform/sound.ts` — звуки, синтезируются WebAudio (без файлов).
- `src/ui` — интерфейс поверх canvas (HUD, окна).
- `src/i18n` — переводы ru/en.
- `src/platform/telegram.ts` — обёртка над Telegram WebApp API. Вне Telegram ничего не делает.

## Автопроверка перед переделками (`npm run e2e`)

Страховка для больших правок (свет, люди, разрезание `StoreScene`): игра собирается, открывается в
Chromium без экрана, магазин середины игры (`e2e/save.json`, день 111) проживает целый день на скорости ×2
до окна итогов, с ночной сменой, и по дороге снимаются одни и те же кадры: утро, день, вечер, ночь, итоги,
дождливый день и ещё два уровня магазина. Игрок при этом стоит за своей кассой: раз в секунду касается её,
как живой. Занимает пару минут.

- Ошибки в странице, зависший день или не открывшееся окно итогов — провал (код выхода 1). Так же —
  файл со своего адреса, который не загрузился (404, обрыв или страница игры вместо файла — так `vite preview`
  отвечает на несуществующий; сервер `/api/` и чужие адреса не в счёт),
  и картинки мира, пришедшие не листом атласа (`atlas0`…).
- Кадры совпадают от запуска к запуску до точки: время в странице своё (кадр ровно через 16 мс),
  случайные числа — с одним зерном, звук выключен.
- Снимки — в `e2e/shots`, там же `report.json`: сколько вызовов отрисовки и смен текстуры в кадре.

Как пользоваться:

```bash
npm run e2e -- --update   # до переделки: снимки → эталон e2e/baseline
# ...правки...
npm run e2e               # после: каждый кадр сравнивается с эталоном, отличия красным в e2e/diff
```

Ключи: `--no-build` (взять готовую `dist/`), `--url http://localhost:5173/` (проверить уже запущенную игру),
`--only l5|rain|l3|l2` (один прогон; с `--update` в эталоне меняются только его кадры и строки `report.json`), `--threshold 0.001` (допустимая доля отличающихся точек),
`--port 4180` (порт своего сервера). Эталон сравним только с тем же компьютером: снимайте его там же,
где проверяете. Нужен Playwright с Chromium: `npm i -D playwright && npx playwright install chromium`
(или свой Chromium в переменной `CHROMIUM_PATH`). В сборку для Cloudflare проверка не входит.

## Подключение к Telegram

1. Создать бота в @BotFather.
2. Задеплоить `dist/` (например, на Vercel).
3. В BotFather: `/newapp` или Bot Settings → Menu Button, указать URL игры.

## Покупки за звёзды (Telegram Stars)

Премиальное оформление продаётся за звёзды. Сервер — несколько маленьких функций без своей базы:
что купил игрок, он узнаёт из платежей бота (`getStarTransactions`). Логика — в `api/_lib/`,
обёртки для двух хостингов: `api/*.ts` (Vercel) и `worker/index.ts` (Cloudflare Workers).

Секреты (только в настройках хостинга, никогда в коде или чате):
- `BOT_TOKEN` — токен бота из @BotFather;
- `WEBHOOK_SECRET` — длинная случайная строка из латинских букв, цифр, `_` и `-`.

### Cloudflare Workers (бесплатно)

Настройки — в `wrangler.jsonc`: игра раздаётся из `dist`, запросы `/api/*` обрабатывает `worker/index.ts`.

1. dash.cloudflare.com → Workers & Pages → Create → Import a repository → этот репозиторий.
2. Build command: `npm run build`, Deploy command: `npx wrangler deploy` (так и предлагается по умолчанию).
3. Settings → Variables and Secrets → добавить `BOT_TOKEN` и `WEBHOOK_SECRET` с типом Secret.
4. Один раз открыть `https://<проект>.<аккаунт>.workers.dev/api/stars-setup?key=<WEBHOOK_SECRET>` — вебхук бота переедет на Cloudflare.
5. В @BotFather поменять адрес мини-приложения (и кнопки меню) на адрес `workers.dev`.

### Vercel

1. Деплой из этого репозитория (папка `api/` подхватится сама).
2. Settings → Environment Variables → `BOT_TOKEN`, `WEBHOOK_SECRET`, затем Redeploy.
3. Один раз открыть `https://<адрес игры>/api/stars-setup?key=<WEBHOOK_SECRET>`.

Открытие `/api/stars-setup?key=…` заодно заполняет профиль бота: описание и короткое описание
(ru/en), команды `/start`, `/paysupport`, `/terms` и кнопку меню «Играть». Аватарку бот поставить
сам не может — её загружают в @BotFather (`/setuserpic`, файл `public/icon-512.png`).

### Поддержка и возврат звёзд

Telegram требует от ботов, которые продают за звёзды, команды `/paysupport` и `/terms` — они есть
(`api/_lib/botProfile.ts`, контакт поддержки — `SUPPORT`). В ответ на `/paysupport` бот сообщает
игроку его номер покупателя. По этому номеру:

- `/api/stars-refund?key=<WEBHOOK_SECRET>&user=<номер>` — все платежи игрока (`charge`, вещь, дата, был ли возврат);
- `/api/stars-refund?key=<WEBHOOK_SECRET>&user=<номер>&charge=<charge>` — вернуть звёзды за этот платёж
  (вещь из игры пропадёт сама: купленное считается по платежам без возвратов).

Без секретов игра работает как раньше, а кнопка покупки честно пишет, что оплата недоступна.
Каждую премиальную вещь можно один раз бесплатно примерить на день.

## Друзья и напоминания от бота (только Cloudflare)

- **«Пригласи друзей»** (профиль 🏆): ссылка `t.me/<бот>?startapp=ref_<id>` открывает игру сразу, без
  чата с ботом (старые `?start=ref_<id>` тоже работают). За каждого друга, который начал играть, —
  500 💰, другу — 300 💰 на старт (один раз). В Telegram 8.0+ делимся через окно «Поделиться» карточкой
  с кнопкой «Играть» — для этого в @BotFather нужно включить *Inline Mode* (без него — обычной ссылкой).
- **«Позвать на помощь»**: в час пик — кнопка 🤝; друг открывает ссылку, и подмога уходит сама (обоим
  монеты, хозяину — быстрая касса на день). Подробнее и защита от накрутки — `docs/PROMO.md`, раздел 6.
- **Напоминания**: раз в час (cron в `wrangler.jsonc`) бот пишет тем, кто не заходил почти сутки, —
  днём, не чаще раза в день и не больше трёх раз подряд; заблокировавшим бота не пишет.

Нужна база Cloudflare D1 (уже подключена в `wrangler.jsonc`; для своего форка — так):

1. Cloudflare → Storage & Databases → D1 → Create, имя `magazinchik`; скопировать Database ID.
2. Добавить в `wrangler.jsonc`:
   `"d1_databases": [{ "binding": "DB", "database_name": "magazinchik", "database_id": "<ID>" }]`.
   Таблицы создаются сами.

Без базы игра работает как раньше, просто без этих двух функций.
